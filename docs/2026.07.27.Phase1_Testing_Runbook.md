## Test 1: Manual Triage of Single Issue

### Setup

Create a test feedback issue manually:

```bash
# Option 1: Via browser (easiest)
open "https://github.com/kilo9alfa/softwarefactory/issues/new?labels=feedback/triage&title=TEST%3A%20Example%20Bug&body=This%20is%20a%20test%20bug%20report."

# Option 2: Via CLI (if gh supports it in your version)
gh issue create --repo kilo9alfa/softwarefactory \
  --title "TEST: Example Bug Report" \
  --body "This is a test issue to verify triage agent works correctly." \
  --label "feedback/triage"
```

Note the issue number (e.g., #5).

### Run Triage Agent

```bash
cd ~/code/softwarefactory

# Run the triage skill directly (bypasses dispatcher)
claude --dangerously-skip-permissions -p /sf-triage 5
```

**Expected output:**
- Agent fetches issue #5 via `gh`
- Agent classifies as `bug` (because it mentions bug)
- Agent outputs JSON with `classification: "bug"`
- Dispatcher (or manual follow-up) updates issue label to `feedback/bug`

### Verify Result

```bash
# Check the issue labels
gh issue view 5 --repo kilo9alfa/softwarefactory --json labels

# Expected: labels array should contain `feedback/bug` (not `feedback/triage`)
```

## Test 2: Dispatcher Manual Run

### Setup

Create 2-3 test issues with `feedback/triage` label (use browser or CLI as above).

### Run Dispatcher

```bash
# Manually trigger one dispatcher cycle
cd ~/code/softwarefactory
bash scripts/sf-dispatcher.sh

# Watch logs
tail -f ~/.local/share/softwarefactory/logs/dispatcher.log
```

**Expected behavior:**
- Dispatcher finds all `feedback/triage` issues
- For each issue, spawns a tmux session: `sf-triage-N`
- Each session runs `claude -p /sf-triage N`
- Sessions complete and are killed
- Log shows: "Spawning triage agent for issue #N"

### Verify Result

```bash
# Check that issues now have classification labels (not feedback/triage)
gh issue list --repo kilo9alfa/softwarefactory --json number,title,labels

# Expected: Each test issue should have either:
# - feedback/bug (if it's a bug report)
# - feedback/feature (if it's a feature request)
# - sf:spam (if it looks like spam)
```

## Test 3: Idempotency Check

### Verify Duplicate Sessions Don't Spawn

Create one test issue. Run the dispatcher twice rapidly:

```bash
bash scripts/sf-dispatcher.sh
# (wait 2 seconds, before session completes)
bash scripts/sf-dispatcher.sh
```

**Expected:**
- Second run detects existing session or result label
- Log shows: "Session sf-triage-N already running, skipping" OR "Issue #N already classified"

## Known Issues & Workarounds

**Issue:** `claude -p` command not found or skill not registered  
**Workaround:** Ensure plugin is installed locally with `/plugin install` first

**Issue:** Issue body causes triage agent to hang or crash  
**Workaround:** Check that skill treats body as untrusted data; review logs in tmux session

**Issue:** Systemd timer doesn't run on Nuclaw  
**Workaround:** Check if user-level systemd is enabled; verify `systemctl --user` works

**Issue:** Permission denied on `~/.local/share/softwarefactory/logs`  
**Workaround:** Ensure directory is created with `mkdir -p` before first run

## Rollback Plan

If anything breaks:

1. Stop the timer on Nuclaw: `ssh r5c-1 'systemctl --user stop softwarefactory-dispatcher.timer'`
2. Kill any running triage agents: `ssh r5c-1 'tmux kill-server'` (or selectively: `tmux kill-session -t sf-triage-*`)
3. Remove the systemd units: `ssh r5c-1 'rm ~/.config/systemd/user/softwarefactory-*.{service,timer}'`
4. Reload systemd: `ssh r5c-1 'systemctl --user daemon-reload'`
5. Revert code changes: `cd ~/code/softwarefactory && git reset --hard HEAD~1`
